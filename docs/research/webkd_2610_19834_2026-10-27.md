# WebKD — reading notes and relevance to the coding-agent experiments

Read on 2026-10-27. Primary source: Ishmam and Marino, *Teaching Agents in
their Own Style: Blackbox Teacher Distillation for Web Agents*, arXiv:2610.19834v1
(14 October 2026). The PDF labels itself a preprint; no accepted venue is claimed.

- Paper: https://arxiv.org/pdf/2610.19834
- Project: https://web-teach-kd.github.io/
- Public code: https://github.com/sparklabutah/webKD
- Implementation explanations checked: `docs/method.md`, `docs/data.md`,
  `docs/training.md` in the public repository. That repository explicitly does
  not distribute experiment trajectories, checkpoints or run-specific configs.

## Problem and scope

Offline behavior cloning supplies teacher-visited states and teacher-written
responses. The paper separates state distribution mismatch from excess surprisal
on teacher wording (the "perplexity premium"). High surprisal alone does not
identify style as the cause: it can also reflect new knowledge or reasoning.
Teacher-style versus student-style editing ablations help test the hypothesis.

Their structured web response is think/plan/step/memory/action. The harness keeps
the latest observation and response history, with explicit scratchpad memory.
This differs from our native Bash-tool coding harness and its accumulated tool
observations. Their web loops are not necessarily intra-turn `<think>` loops.

## Pipeline (Sections 3.3, B.1–B.3)

1. P1: seed student using ordinary BC on successful teacher trajectories.
2. P2: run the BC checkpoint on training tasks. Failures supply correction states;
   solved episodes preferentially supply style exemplars.
3. P3: teacher localizes the first erroneous step. Original responses before that
   step are preserved.
4. P4: independently edit each later response at the **original student context**.
   Three rationale exemplars from other student tasks condition wording, excluding
   their actions. Teacher reasoning and decisions should remain correct; copying
   the student's mistakes is not the objective.
5. Filter state-inconsistent corrections and train on per-step `(context, target)`
   records, not a stitched trajectory produced by executing the corrected suffix.

**Corrections are never executed during data construction.** Original actions and
response histories determine every subsequent observation. Concatenating a new
action with the old next observation would violate this construction. A coding
adaptation must either retain independent step records or execute corrections to
obtain new states. Their lexical grounding filter is not a semantic correctness
verifier for Python or a replacement for executing reproduction/tests.

## Action-informativeness weighting (Equations 4, 10–12)

For each rationale span s and teacher-corrected action a*:

    Delta_s = log P_ref(a* | h, full corrected rationale)
            - log P_ref(a* | h, corrected rationale with s removed)

`ref` is the frozen **BC seed student**, not the black-box teacher. Both scores
are teacher-forced log-probabilities of the same action. Sentences/lines are
segmented, short fragments merged, and each response capped at 24 spans.

Within-step average ranks of Delta map to weights in [0.1, 1], using a 0.05-nat
dead zone; near-identical contributions get near-midpoint weights. Negative
contributions remain in the ranking rather than being hard-masked. Token weights
use character-overlap averaging. Actions, step indices and response-envelope
tokens retain weight 1.

This is not a fixed low weight on all reasoning, and it does not certify that a
span is logically correct. It measures how removing it changes this particular
student's probability of one proposed action. Redundant/supporting spans, shared
lexical cues and reasoning interactions can confound this proxy.

## Objective (Equation 5; Appendix B.6)

    L = sum_i w_i CE_i / sum_i w_i
        + beta * sum_i gamma_i (exp(d_i) - d_i - 1) / sum_i gamma_i
    d_i = log pi_ref(y_i* | prefix) - log pi_theta(y_i* | prefix)

The implementation clamps d to [-20, 8]. Default beta is .03. Rationale tokens
have gamma=1; action/step tokens effectively have gamma=1e-6, with envelope-token
handling documented separately in code. CE weights and anchor masks are separate.

The anchor is **a target-token k3 penalty on corpus tokens**, not full-vocabulary
KL or an unbiased KL estimator in this offline setting. k3 has the stated
unbiasedness only when taking expectations over student-policy samples. At
initialization current=reference, the anchor gradient is zero; it constrains later
drift. Token-local guarantees are not guarantees of retained global competence.

The weighted CE denominator is the sum of weights. This is not our prior hybrid
group-length normalization. Their combined loss averages each support within a
microbatch; with unequal lengths, averaging microbatch losses differs from one
global token mean.

## Evidence

TimeWarp v6 test, Qwen3.5-4B (Table 1):

| Method | Success rate |
|---|---:|
| Zero-shot | 1.0% |
| BC with full structured responses (TW) | 29.8% |
| m-GRPO | 30.4% |
| WebKD | 41.1% |

WebKD gains 10.7 percentage points over the strongest listed baseline for this
model. It is not a SWE-bench result. Their base web agent starts near zero, unlike
the capable coding base observed in our earlier task.

Table 2 (same WebKD objective): teacher-style edits 33.01%, teacher edits with
in-context student style 41.10%, student re-styling after teacher editing 25.89%.

Table 3 (same correction setting): uniform CE without/with anchor 36.25/37.43%;
action-informed weighted CE without/with anchor 38.51/41.10%. These ablations are
more relevant to loss design than comparing the full pipeline against ordinary BC.

Appendix D.2: WebKD action/navigation loops ~8.7%, BC-TW ~19.4%, m-GRPO ~15.5%.
These labels do not establish reductions in our intra-turn reasoning repetition.

The discussion reports Qwen3.8-27B as editor gives 26.9%, versus GPT-5.5 41.1%.
This motivates checking teacher quality, not declaring our Qwen trajectory pool
defective on the basis of a different benchmark. Appendix D.1's longer-BC plateau
is on Qwen3.5-9B in TimeWarp, not proof against undertraining in our experiments.

## Actual scale and cost (Appendix C.3, Table 4)

- 15 failed training episodes -> 432 step records: 403 edited + 29 replayed.
- Grounding removes 40 edited records -> 392 retained records.
- Edited response targets ~64k tokens; repeated long contexts add compute.
- Full-parameter BF16 tuning, 2 epochs, LR1e-5, effective batch16, context cutoff
  20,480; ZeRO-3, CPU optimizer offload, one H200; reported 1 GPU-hour/fine-tune.
- Localization: 15 teacher calls, .47M prompt tokens. Editing: 403 calls, 4.0M
  prompt tokens. Counts exclude some missing/hidden tokens.
- Offline leave-one-out scoring requires a full score and up to 24 ablation
  scores per edited step. It needs student log-probs, not just generated text.
- Reference implementation keeps a second frozen model and an extra forward per
  microbatch. LoRA on one 5090 is a proposed adaptation, not their measured setup.
- Their 103-task web evaluation timings are not a cost estimate for 500 coding
  tasks with accumulated 35k+ contexts and executable test environments.

## Implications for our next experiment — hypotheses, not established results

1. Measure frozen-student NLL separately for teacher/student reasoning and actions
   on matched states before assigning the degradation to teacher style.
2. Use a checked vanilla-SFT seed as the reference. Anchoring an already damaged
   policy does not automatically restore the original base's competence.
3. Run student on **training/development** tasks; reserve unseen tasks for final
   testing. Reusing heavily debugged Verified tasks is not an independent test.
4. Start by comparing ordinary CE against action-informed weights on the same
   successful coding corpus; call this a weighting adaptation, not full WebKD.
   A faithful WebKD-style study additionally requires student-state correction.
5. For a full pipeline, separate action/submit and preserve native tool syntax;
   test edited actions against repository observations rather than transplanting
   web tags or trusting lexical grounding.
6. Frozen-reference target log-probs can in principle be precomputed for immutable
   tokenized `(context, target)` records and reused by the pointwise anchor. This
   avoids a second resident model during training, but requires exact template,
   masks, checkpoint identity and token alignment. This is our engineering idea,
   not a reported optimization in the paper.
7. Ablate one component at a time with the same source records, split and compute.
   Style editing + weights + anchor together cannot attribute the improvement to
   any one component, and applying the web method to coding alone does not yet
   establish a new research contribution.
